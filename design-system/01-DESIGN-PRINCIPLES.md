# 01 — Design Principles

> `main` 分支适用的设计修改原则。
> 这些原则优先于任何 AI 工具的默认设计倾向。

## 核心原则

### 1. 保留现有结构

现有 HTML 结构和 CSS 架构有明确的存在理由。修改应是在现有结构上调整，而不是重组或替换。

- 不要删除已有的 section
- 不要重写 card 组件的 HTML 结构
- 不要改变页面内容流顺序

### 2. 优先局部 Polish

改进应该是小范围的、可回退的、独立的。

- ✅ 调整某个组件的间距
- ✅ 修改颜色或圆角值
- ✅ 优化某段文案
- ❌ 把一个 section 的布局从网格改为 flex
- ❌ 重新设计整个 Hero 区域

### 3. 作品内容优先

网站的核心价值是展示内容（38 个 PPT + 6 个项目），设计是内容的容器，不是内容本身。

- 封面图必须保持真实可见
- 交互功能（筛选、搜索、展开/收起）不能因视觉改动而损坏
- 所有链接必须保持有效

### 4. 功能稳定优先

不要因为"视觉效果更好看"而牺牲已通过测试的功能。

- PPT 筛选 + 搜索行为不能改变
- 点赞流程（乐观更新 → API 同步 → 回退）不能改变
- 移动端重定向逻辑不能改变

### 5. 移动端不能被牺牲

任何桌面端改动必须在 mobile.html 中有对应同步。

- `css/style.css` 改动 → 同步到 `css/mobile-legacy.css`
- 移动端交互（触摸目标 ≥44px）不能被破坏
- 移动端加载性能优先于装饰

### 6. 克制胜于装饰

- 每一条线、每一个颜色、每一次动效必须有功能理由
- 不添加"看起来不错但没有功能"的视觉元素
- 不动效超过 500ms（入场动效除外）

### 7. 设计 Token 优先

所有颜色、间距、字号从 `:root` 变量中读取，不使用任意值。

- 颜色：`--primary`、`--text-main`、`--text-sub`、`--text-muted`、`--border` 等
- 间距：基于 4pt 系统（4/8/12/16/24/28/32/48）
- 字号：使用 `rem` 或 `clamp()`

### 8. 不做大重构

- 不要切换 CSS 架构（如改为 Tailwind/CSS Modules）
- 不要引入框架（如 React/Vue/Astro）
- 不要新增构建步骤
- 不要添加自定义字体（现有 Google Fonts 已覆盖）
